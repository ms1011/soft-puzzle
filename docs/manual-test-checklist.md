# 수동 테스트 체크리스트

`card-night`는 실제 터미널·실제 LAN에서만 확인할 수 있는 부분(터미널별 렌더링,
브로드캐스트 발견, 방화벽 프롬프트)이 있어 자동화 테스트만으로는 릴리스 확인이
끝나지 않는다. 이 문서는 사람이 두 대(가능하면 세 대) 이상의 기기로 실제 실행해
봐야 할 항목을 정리한 것이다.

각 항목은 실행한 사람이 결과(환경·날짜·통과 여부)를 문서 맨 아래 "실행 기록"
표에 남긴다.

## 준비물

- 같은 와이파이/공유기에 연결된 기기 2대 이상 (호스트 1 + 참가자 1 이상)
- 아래 환경 중 최소 하나씩:
  - macOS Terminal.app (또는 iTerm2)
  - Windows Terminal
  - 구형 Windows PowerShell / `cmd.exe` (conhost — Windows Terminal이 아닌 옛날
    콘솔 창)
- `npm install -g card-night` 또는 `npx card-night`로 설치·실행할 수 있는 Node
  22+ 환경

## A. 설치·실행 기본

- [ ] `npm install -g card-night` (또는 `npx card-night`)로 설치·실행된다.
- [ ] 첫 실행 시 방화벽 허용 팝업이 뜬다(호스트가 되거나 방을 찾을 때). **허용**을
      누르면 정상 동작한다.
- [ ] 닉네임을 입력하면 다음 실행부터 저장된 닉네임으로 바로 메인 메뉴가 뜬다.
- [ ] 한글이 메뉴·로비·게임 화면 전체에서 깨지지 않고 표시된다(닉네임, 방 이름,
      카테고리 라벨, 안내 문구 전부).
- [ ] 아무 화면에서나 Ctrl+C로 종료하면 터미널이 raw mode에서 정상 복원된다
      (프롬프트가 이상해지거나 입력이 안 보이지 않는다).

## B. 아트 렌더링

- [ ] 옵션 없이 실행하면(최신 macOS Terminal/Windows Terminal) 카드·주사위가
      박스 문자(┌─┐)와 무늬 기호(♠♥♦♣)로 그려진다.
- [ ] `card-night --ascii`로 실행하면 같은 화면이 순수 ASCII(+, -, S/H/D/C 등)로
      그려지고 레이아웃 폭이 유니코드 모드와 같다(카드 흔들림 없음).
- [ ] 구형 PowerShell/conhost에서는 `--ascii` 없이 실행해도 **자동으로** ASCII로
      그려진다(Windows Terminal/ConEmu가 아닌 win32 자동 감지).

## C. 방 발견·연결

- [ ] 호스트가 방을 만들면 참가자 기기의 "방 참가" 화면에 몇 초 안에 그 방이
      뜬다.
- [ ] **실제 두 기기 간 UDP 브로드캐스트 팬아웃**: 참가자 기기가 2대 이상일 때
      한 번의 브로드캐스트로 여러 응답기가 동시에 잡히는지 확인한다(포트 공유
      환경에서 한 대만 응답하는 회귀가 없는지).
- [ ] **호스트 자신도 참가자로 그 방에 들어가 있는 상태**에서, 다른 기기가 방
      목록을 스캔했을 때 그 방이 **정확히 한 번만** 보인다(loopback 응답과 LAN
      응답이 중복으로 두 줄 뜨지 않는다).
- [ ] 방화벽/네트워크 문제로 방 목록이 비어 있을 때, 참가자가 **[i] IP 직접
      입력**으로 호스트가 불러준 `192.168.x.x:포트`를 입력해 접속할 수 있다.
- [ ] 같은 닉네임(예: 한쪽은 macOS, 한쪽은 Windows)으로 입장을 시도하면 **중복
      거절**되고 새 닉네임을 입력하라는 화면으로 돌아간다 — 두 명이 같은 이름으로
      동시에 들어가 있는 상태가 되지 않는다.

## D. 게임 3종 각 1판

- [ ] **블랙잭**: 베팅 → 히트/스탠드/더블다운 → 딜러 정산까지 한 판을 끝까지
      진행하고, 호스트가 [e] 게임 종료로 결과 화면까지 도달한다.
- [ ] **원카드**: 카드 내기(7 낼 때 무늬 선택 포함)·뽑기를 거쳐 누군가 손패를
      비울 때까지 진행해 결과 화면을 본다.
- [ ] **야추**: 리롤·홀드·점수 기록을 13개 카테고리 다 채울 때까지 진행해 결과
      화면(순위)을 본다.
- [ ] **야추 점수표 — 3인 이상, 80칼럼 터미널**: 터미널 폭을 80칼럼으로 맞추고
      3명 이상이 참여한 야추 판에서 점수표가 줄바꿈으로 깨지지 않는지 확인한다.
- [ ] **야추 점수표 — 긴 한글 닉네임**: 8칸(표시 폭) 넘는 닉네임으로 참여했을 때
      그 칸만 잘려 보이고 표 전체 폭이 밀리지 않는지 확인한다.

## E. 이탈·타임아웃

- [ ] **참가자 강제 종료**: 게임 중 참가자 한 명이 창을 닫거나 Ctrl+C로 나가면,
      남은 사람들 게임은 멈추지 않고 계속된다.
- [ ] **호스트 강제 종료**: 호스트가 Ctrl+C로 나가면, 나머지 전원이 "방장의
      연결이 끊겼습니다" 화면을 보고 [Enter]로 메인 메뉴로 돌아갈 수 있다.
- [ ] **턴 타임아웃 자동 처리**: 자기 턴에 90초간 아무 키도 누르지 않으면 서버가
      자동으로 기본 행동을 대신 진행하고 게임이 멈추지 않는다.
- [ ] 호스트/참가자 모두, 종료 후 그 기기에서 `card-night` 프로세스가 남아있지
      않다(터미널 프롬프트가 바로 돌아온다).

## 실행 기록

아래는 이 태스크를 구현하며 **이 개발 환경(단일 macOS/Darwin 25.3.0 샌드박스,
물리적으로 한 대뿐, 실제 두 번째 기기·Windows 없음)에서 실제로 실행해 확인한
것**이다. `card-night`를 빌드해 tarball로 만들고 `npm install -g`로 스크래치
디렉터리에 설치한 뒤, 그 설치된 바이너리를 pty(의사 터미널)로 직접 구동해
관찰했다 — 소스 실행이 아니라 **설치된 배포물**을 실행한 결과다. 여러 참가자가
필요한 항목은 같은 기기에서 `card-night` 프로세스를 2~3개 띄워 `127.0.0.1`로
서로 접속시켜 재현했다(TCP/UDP 코드 경로 자체는 LAN IP든 loopback이든 동일하지만,
실제 두 기기 사이의 물리적 네트워크·방화벽·Windows 자체는 이 방법으로 검증할
수 없다 — 그 부분은 사람이 남았다).

### 이 환경에서 확인하지 못한 것 (사람이 실제 기기로 확인해야 함)

- **실제 Windows Terminal**, **구형 Windows PowerShell/`cmd.exe`(conhost)**에서의
  실행·한글 표시·`--ascii` 자동 감지 — 이 환경은 Darwin뿐이라 `win32` 분기
  자체는 단위 테스트(`detectTheme`)로만 확인됐고 실제 conhost 렌더는 검증되지
  않았다.
- **물리적으로 분리된 두 대 이상의 기기** 사이의 실제 LAN 브로드캐스트(같은
  공유기, 서로 다른 네트워크 인터페이스·방화벽 상태)와 그 환경에서의 방화벽
  최초 허용 팝업. 이 세션의 검증은 전부 같은 머신에서 `127.0.0.1`로 이뤄졌다 —
  코드 경로는 LAN IP와 동일하지만 실제 라우터를 넘는 브로드캐스트 전달 자체는
  이 방법으로는 증명되지 않는다.
- **원카드·야추 한 판을 끝까지(결과 화면까지) 진행하는 것** — 야추는 첫 턴
  화면(점수표 레이아웃)까지만, 원카드는 이번 세션에서 별도로 진행하지 않았다.
  블랙잭도 최종 결과 화면까지는 도달하지 못했다(라운드 루프는 확인).
- **턴 타임아웃(90초) 자동 처리** — 실시간으로 90초를 기다리는 검증은 이번
  세션에서 수행하지 않았다(엔진의 타임아웃 로직 자체는 서버 자동화 테스트가
  이미 커버한다).
- **두 번째 물리 기기가 방을 찾을 때 "정확히 한 번만" 보이는지** — 이번 세션은
  같은 머신의 두 프로세스로 loopback/LAN 이중 응답 제거 로직만 확인했다. 서로
  다른 서브넷 인터페이스(VPN 등)를 가진 진짜 호스트 머신에서 참가자 쪽 목록이
  중복되지 않는지는 실제 두 기기로 재확인이 필요하다.
