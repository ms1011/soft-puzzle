# card-night — CLI 멀티플레이 카드 게임 기획서

- 작성일: 2026-08-28
- 상태: 설계 승인됨 (구현 계획 수립 전)
- 프로젝트명 `card-night`는 가칭이며 변경 가능

## 1. 개요

같은 네트워크(LAN)에 있는 사내 동료·친구끼리 터미널에서 즐기는 멀티플레이 카드 게임.
Windows(PowerShell)와 mac(Terminal) 양쪽을 지원하며, 딜러는 컴퓨터가 진행한다.

- **목적**: 사내/친구끼리 실사용 — 안정성과 접속 편의성이 최우선
- **게임 종류**: 야추, 섯다, 고스톱, 블랙잭, 포커, 원카드 (총 6종)
- **MVP(1차)**: 블랙잭, 원카드, 야추 + 공통 인프라
- **2차**: 섯다, 포커, 고스톱, 호스트 이전, 진행 중 판 재접속

## 2. 확정 요구사항

| 항목 | 결정 |
|---|---|
| 기술 스택 | Node.js / TypeScript |
| 서버 구조 | 방장 호스트 — 방 만든 사람의 프로세스가 서버 겸임 |
| UI | 풀스크린 TUI (Ink), 카드·주사위 ASCII 아트 |
| 방 참가 | LAN 자동 발견(UDP 브로드캐스트) + IP 직접 입력 폴백 |
| 칩 | 판(방 세션)마다 리셋, 저장 없음 |
| 최대 인원 | 방당 6명 |
| 배포 | npm 패키지 — 모두 Node가 설치되어 있어 `npm i -g`/`npx`로 실행 |

## 3. 아키텍처 — 서버 권위 + 개인화 뷰 스냅샷

호스트가 모든 게임 상태(덱, 패, 턴)를 단독 소유한다. 클라이언트는 의도(action)만
보내고, 호스트가 규칙을 검증한 뒤 **각 플레이어가 볼 수 있는 것만 담은 상태
스냅샷**을 보낸다. 클라이언트는 받은 스냅샷을 그대로 그리는 렌더러다.

- 치팅 원천 차단: 남의 패 정보가 네트워크로 나가지 않음
- 클라이언트 단순화: 게임 규칙을 전혀 몰라도 됨
- 게임 추가 = 서버 쪽 상태머신 1개 + 클라이언트 쪽 화면 1개

```
┌─────────────── 방장 PC ───────────────┐      ┌──── 참가자 PC ────┐
│  ┌─ 서버 (게임 엔진) ─────────────┐   │      │                    │
│  │ 로비 관리 · 게임 상태머신      │   │ TCP  │  클라이언트        │
│  │ 덱/주사위 · 규칙 검증 · 딜러   │◀──┼──────┼─▶ (TUI 렌더러)     │
│  └───────────────────────────────┘   │      │                    │
│  클라이언트 (TUI 렌더러) ── 내부접속  │      └────────────────────┘
│  UDP 브로드캐스트 응답기 (방 알림)    │
└───────────────────────────────────────┘
```

사용자는 실행 파일 하나만 사용한다. "방 만들기"를 선택하면 프로세스 안에서 서버가
함께 뜨고 자신도 첫 클라이언트로 접속하며, "방 참가"를 선택하면 클라이언트로만
동작한다.

### 모듈 구성 (모노레포 내 패키지 3개)

| 패키지 | 역할 | 의존 |
|---|---|---|
| `core` | 카드·덱·주사위·족보 판정 등 순수 게임 로직, 게임별 상태머신, 프로토콜 타입 | 없음 (순수 TS) |
| `server` | TCP 서버, 로비/방 관리, 턴 진행, 개인화 뷰 생성, UDP 발견 응답 | core |
| `client` | Ink 기반 TUI, ASCII 아트 렌더링, 입력 처리, 서버 발견/접속 | core |

설계 원칙:

1. **게임 로직은 전부 `core`의 순수 함수/상태머신.** 네트워크·UI와 분리되어 단위
   테스트로 규칙을 검증한다. 셔플은 시드 주입이 가능해야 한다(재현 가능한 테스트).
2. **모든 게임은 공통 인터페이스를 구현한다.**
   `GameEngine { join, start, handleAction, getViewFor(player), isFinished }`
   서버는 어떤 게임인지 모른 채 이 인터페이스로만 진행한다.

## 4. 네트워크 프로토콜

- **전송**: TCP + 줄 단위 JSON (NDJSON). 메시지 하나 = JSON 한 줄.
- **포트**: 게임 TCP `7420`, 발견 UDP `7421`. 충돌 시 자동 +1.

메시지는 세 종류뿐이다:

```jsonc
// 1. 클라이언트 → 서버: 의도(intent)
{"type":"action","name":"hit"}
{"type":"join","nickname":"철수"}
{"type":"chat","text":"ㄱㄱ"}          // 채팅은 선택 기능

// 2. 서버 → 클라이언트: 개인화된 상태 스냅샷 (매 변화마다 통째로)
{"type":"state","phase":"playing","game":"blackjack",
 "you":{"hand":["KH","7D"],"chips":900,"bet":100},
 "others":[{"nick":"영희","handCount":2,"chips":800,"isTurn":true}],
 "dealer":{"visible":["AS"],"hiddenCount":1},
 "yourActions":["hit","stand"]}

// 3. 서버 → 클라이언트: 이벤트 로그 (화면 하단 알림)
{"type":"event","text":"영희님이 카드를 뽑았습니다"}
```

`yourActions`가 핵심이다. 서버가 "지금 가능한 행동 목록"을 내려주고 클라이언트는
그것만 그린다. 서버는 들어온 action을 "그 플레이어의 현재 `yourActions`에
있는가"로만 검증하고, 아니면 조용히 무시한다. 순서 꼬임·중복 입력·조작된
클라이언트를 이 한 겹으로 방어한다.

### 방 발견 (UDP 브로드캐스트)

1. 참가자 앱이 `255.255.255.255:7421`로 `WHO_IS_THERE` 전송 (1초 간격 3회)
2. 방장 프로세스가 응답:
   `{"room":"철수의 방","game":"blackjack","players":"2/6","addr":"192.168.0.5:7420"}`
3. 참가자 화면에 방 목록 표시, 선택 시 TCP 접속
4. 목록이 비면 "IP 직접 입력" 메뉴로 폴백. 방장 화면에는 항상 자기 IP:포트 표시.

## 5. 화면 흐름과 UX

```
시작 ──▶ 닉네임 입력 ──▶ 메인 메뉴 ──┬─▶ 방 만들기 ─▶ 게임 선택 ─▶ 로비(대기) ─┐
                          ▲          └─▶ 방 참가 ──▶ 방 목록/IP 입력 ─▶ 로비 ──┤
                          │                                                    ▼
                          └──── 결과 화면 (다시하기/나가기) ◀──── 게임 플레이 ◀┘
```

- 닉네임은 최초 1회 입력 후 `~/.card-night.json`에 저장 — 다음 실행부터 바로 메뉴.
- 로비: 참가자 목록 실시간 갱신, 방장이 [시작]을 눌러 게임 개시.
- 판 종료 후 결과 화면 → 방장이 "다시하기"를 누르면 같은 멤버로 새 판(칩 리셋).
- 입력: 단축키 한 글자 즉시 반응 (Hit=`h`, Stand=`s`, 주사위 홀드=`1`~`5`,
  확인=`Enter`). 하단에 현재 가능한 키 안내 바 상시 표시(`yourActions` 기반).

### ASCII 아트

카드 — 가로 7칸 × 세로 5줄 (실제 카드처럼 세로가 약간 긴 비율). 패가 많으면 겹쳐
그린다:

```
┌─────┐ ┌─────┐ ┌─────┐ ┌─┌─┌─────┐
│K    │ │A    │ │▒▒▒▒▒│ │ │ │7    │
│  ♥  │ │  ♠  │ │▒▒▒▒▒│ │ │ │  ♣  │
│    K│ │    A│ │▒▒▒▒▒│ │ │ │    7│
└─────┘ └─────┘ └─────┘ └─└─└─────┘
  하트K   스페이드A  뒷면     겹침(원카드)
```

주사위 — **가로 9칸 × 세로 5줄** (터미널 글자의 세로:가로 ≈ 2:1을 보정해 시각적
정사각형). 홀드한 주사위는 이중선 테두리:

```
┌───────┐ ┌───────┐ ┌───────┐ ╔═══════╗ ╔═══════╗
│ ●     │ │ ●   ● │ │ ●   ● │ ║ ●   ● ║ ║ ● ● ● ║
│   ●   │ │       │ │   ●   │ ║       ║ ║ ● ● ● ║
│     ● │ │ ●   ● │ │ ●   ● │ ║ ●   ● ║ ╚═══════╝
└───────┘ └───────┘ └───────┘ ╚═══════╝   [잡음]
    3         4         5      ← 이중선 = 홀드
```

- 색상: 하트·다이아 빨강, 스페이드·클럽 흰색/검정, 내 턴은 노란 강조.
- 화투(고스톱·섯다) 아트는 2차 범위 — 월별 약칭 + 광·띠·피 구분 표시로 별도 디자인.

### Windows 호환성

구형 PowerShell 콘솔(conhost)은 유니코드 무늬·박스 문자가 깨질 수 있다. 시작 시
터미널 환경을 감지해 문제가 있으면 `--ascii` 폴백 모드로 자동 전환한다: 무늬는
`S H D C` 문자, 테두리는 `+--+`, 주사위도 같은 정사각형 비율 유지. Windows
Terminal·mac Terminal에서는 풀 유니코드 렌더링.

## 6. MVP 게임 3종 규칙

지역 변형 룰은 두지 않는다. 아래 룰이 고정 룰이며, 방 옵션화 계획도 없다.

### 블랙잭 (2~6인 + 컴퓨터 딜러, 칩 사용)

- 방 입장 시 전원 칩 1,000.
- 라운드: 베팅 → 딜 → 각자 Hit / Stand / Double → 딜러 공개(17 이상까지 뽑음,
  Soft 17 스탠드) → 정산(블랙잭 1.5배).
- 칩 0이 되면 그 판은 관전, "다시하기" 때 1,000으로 복귀.
- **제외**: 스플릿, 보험, 서렌더 (복잡도 대비 재미 기여 낮음 — 2차 후보).

### 원카드 (2~6인, 순위제)

- 조커 2장 포함 54장. 시작 7장. 같은 무늬 또는 같은 숫자를 내고, 못 내면 1장 드로우.
- 먼저 다 털면 승리, 이후 터는 순서로 순위. 손패 15장 도달 시 파산 탈락.
- 특수 카드:
  - **2**: +2장 공격
  - **A**: +3장 공격
  - **흑 조커**: +5장 공격, 검정 무늬(♠♣) 위에만 낼 수 있음
  - **적 조커**: +7장 공격, 빨강 무늬(♥♦) 위에만 낼 수 있음
  - **J**: 다음 사람 건너뜀
  - **Q**: 방향 전환
  - **K**: 한 번 더 냄
  - **7**: 무늬 변경 선언
- 공격은 같은 종류 공격 카드로 되받아 누적 가능 — 2는 2로, A는 A로, 조커는
  조커로(흑/적 무관, 단 색 제약은 바닥 카드 기준 적용). 되받지 못하면 누적된
  장수를 한 번에 드로우하고 턴이 넘어간다. **3 방어는 없다.**

### 야추 (1~6인, 점수제 — 혼자 연습도 가능)

- 주사위 5개, 턴마다 최대 3회 굴림, 굴림 사이 홀드(`1`~`5` 키) 자유.
- 표준 점수표 13항목: 에이스~식스(상단), 3·4 of a Kind, 풀하우스(25),
  S 스트레이트(30), L 스트레이트(40), 야추(50), 찬스.
- 상단 합 63점 이상이면 보너스 +35.
- 13라운드 후 총점 순위. 점수표는 화면 우측 상시 표시, 기록 항목은 커서로 선택.

### 공통 진행 규칙

- 턴 제한시간 90초 — 초과 시 자동 처리(블랙잭 Stand, 원카드 드로우, 야추 찬스에
  강제 기록). 잠수로 게임이 멈추는 것을 방지한다.
- 컴퓨터 딜러의 진행 멘트(셔플, 딜, 결과 선언)는 이벤트 로그 영역에 대사체로
  출력해 딜러 존재감을 살린다.

## 7. 이탈·끊김 처리

**참가자 이탈** (TCP 끊김 즉시 감지)

- 진행 중인 판: 자동 처리로 전환 — 블랙잭은 Stand 후 정산만, 원카드는 손패를
  버리고 탈락, 야추는 남은 라운드 0점.
- 판 종료 후 방에서 제거. 같은 닉네임으로 로비 복귀는 가능하나 **진행 중인 판
  복귀는 1차 미지원** (2차 후보).

**방장(호스트) 이탈**

- 1차: 서버가 함께 종료되므로 게임 종료. 참가자에게 "방장의 연결이 끊겼습니다"
  안내 후 메인 메뉴 복귀. 로비에 "방장이 나가면 방이 사라집니다" 안내 문구로
  기대치를 관리한다.
- **2차: 호스트 이전(migration) 지원.** 서버 상태 스냅샷을 참가자에게 주기적으로
  복제해 두고, 호스트 이탈 시 지정된 참가자가 서버를 이어받는 방식으로 설계 예정.

## 8. 테스트 전략

- `core`: 단위 테스트 집중 — 족보 판정, 덱 셔플·분배, 상태머신 전이(예: "공격
  누적 중엔 드로우 외 행동 불가"). `(상태, 행동) → 새 상태` 순수 함수라 테스트
  용이. 시드 셔플로 재현 가능한 테스트 작성.
- `server`: 가짜 소켓 2~3개로 로비 참가 → 시작 → 한 판 완주 통합 테스트.
  **개인화 뷰에 남의 패가 새는지 검사하는 테스트 필수.**
- `client`: `ink-testing-library`로 스냅샷 렌더 확인(ASCII 아트 깨짐 감지).
- 수동 테스트: mac Terminal + Windows Terminal + 구형 PowerShell 3종에서
  체크리스트 실행.

## 9. 배포

- npm 패키지로 배포한다. 사용자 전원이 Node를 갖고 있으므로 `npm i -g card-night`
  또는 `npx card-night`로 실행. (사내 npm 레지스트리 또는 git URL 설치도 가능)
- 단일 실행 파일 패키징(SEA/pkg)은 하지 않는다.

## 10. 범위 정리

**1차 (MVP)**

- 공통 인프라: 로비, UDP 방 발견, TCP 프로토콜, 턴 진행, TUI 프레임
- 게임: 블랙잭, 원카드, 야추
- `--ascii` 폴백 모드

**2차**

- 게임: 섯다, 포커, 고스톱 (+ 화투 ASCII 아트)
- 호스트 이전(방장 이탈 시 다른 플레이어가 방장 승계)
- 진행 중인 판 재접속
- 블랙잭 스플릿 등 제외했던 세부 룰 (필요성이 확인되면)

**비범위 (계획 없음)**

- 인터넷(WAN) 플레이, 계정/영속 칩·전적 저장, 원카드 지역 변형 룰 옵션
