# 고민 중 커서 공유(focus) 설계

- 날짜: 2026-09-22
- 상태: 승인됨
- 관련: [방 채팅 설계](2026-09-22-room-chat-design.md) — `chatRoute`와 같은 구조를 따른다.

## 목적

차례인 사람이 "무엇을 고르고 있는지"를 다른 참가자가 실시간으로 볼 수 있게 한다. 확정된 행동(`action`)이
아니라 확정 전의 커서다. 원카드에서 상대가 어느 카드를 만지작거리는지, 다빈치에서 누가 내 타일을 노리는지가
보이면 CLI 화면에서도 테이블에 마주 앉은 긴장감이 생긴다.

## 범위

| 게임 | 공유 여부 |
|---|---|
| 원카드 | 차례인 사람의 손패 커서 위치 |
| 다빈치 | 차례인 사람이 겨누는 타일(추리 숫자는 제외) |
| 야추 | 차례인 사람이 점수 칸 선택 모드에서 보고 있는 칸 |
| 마피아 | 밤에 살아 있는 마피아가 겨누는 대상 — 마피아끼리만 |
| 마피아 낮 투표·라이어·인디언 포커·블랙잭 | 공유하지 않는다 |

마피아 낮 투표 커서는 숨긴다(사용자 결정). 투표는 원래 비밀이고, 커서를 공개하면 눈치 보기·몰표가 생긴다.

## 접근 방식

**일회성 전달 메시지.** 커서는 엔진 상태에 넣지 않는다. Room이 받은 focus를 엔진의 `focusRoute`에 물어
검증·정리한 뒤, 허용된 수신자에게 전달만 한다.

기각한 대안:
- 엔진 상태에 커서를 저장하고 view로 내보내기 — 커서 한 칸마다 전체 state를 전원에게 다시 보내야 하고,
  화면 표시용 데이터가 모든 엔진 상태에 섞인다.
- 엔진 없이 Room이 전원에게 전달 — 마피아 밤 커서가 시민에게 샌다.

## 프로토콜

```ts
// ClientMsg
{ type: 'focus'; target: unknown }            // null = 고민 중 아님
// ServerMsg
{ type: 'focus'; from: string; target: unknown }
```

호환성: 서버 `Room.handleMessage`와 클라이언트 `App.handleServerMsg`는 모두 모르는 type을 조용히 무시한다.
따라서 버전 협상 없이 옛 서버·새 클라이언트, 새 서버·옛 클라이언트 조합 모두 연결이 유지되고, 커서 공유만
동작하지 않는다.

## 엔진 인터페이스

```ts
export type FocusRoute = { to: string[] | 'all'; target: unknown } | null;

interface GameEngine {
  // 선택. 없으면 그 게임은 focus를 전혀 전달하지 않는다.
  focusRoute?(sender: string, target: unknown): FocusRoute;
}
```

- 엔진은 보낸 사람이 지금 이 커서를 보낼 자격이 있는지(차례인지, 역할이 맞는지) 스스로 확인한다.
- 받은 target을 그대로 돌려주지 않고, 검증한 필드만으로 **새 객체를 만들어** 돌려준다. focus가 막힌 사람
  (밤의 시민·탈락자)의 몰래 쓰는 채팅 통로가 되지 않게 하기 위해서다.
- `target === null`은 형식 검증 없이 허용하되, 자격·수신자 규칙은 똑같이 적용한다.
- `'all'`은 방 전원을 뜻한다. 원카드처럼 완주·파산한 사람을 내부 목록에서 지우는 엔진이 전원 목록을 직접
  만들기 어렵기 때문이다.

### 게임별 규칙

| 게임 | 받는 target | 검증 | 전달 target | 수신자 |
|---|---|---|---|---|
| 원카드 | `{ index }` | 보낸 사람이 차례, `index`는 `0 ≤ index < 손패 장수`인 정수 | `{ index }` | `'all'` |
| 다빈치 | `{ player, index }` | 보낸 사람이 차례, `player`는 탈락하지 않은 상대, 그 타일은 아직 숨김 | `{ player, index }` | `'all'` |
| 야추 | `{ category }` | 보낸 사람이 차례, 아직 기록하지 않은 칸 | `{ category }` | `'all'` |
| 마피아 | `{ target }` | 밤, 보낸 사람이 살아 있는 마피아이고 아직 행동 전, 대상은 살아 있는 다른 사람 | `{ target }` | 살아 있는 마피아 |

그 밖의 경우(마피아 낮, 특수직업, 탈락자, 형식 오류)는 `null`을 돌려준다.

## 서버(Room)

`handleMessage`에 `focus` 분기를 추가한다.

1. `phase === 'playing'`이고 보낸 사람이 `engine.pendingPlayers()`에 있을 때만 처리한다.
2. 한 사람당 1초에 20개를 넘는 focus는 버린다(남용 방지). 시계는 Room에 주입된 `now`를 쓴다.
3. `engine.focusRoute?.(sender, target)`가 `null`이거나 메서드가 없으면 버린다.
4. 수신자 = (`'all'`이면 방 참가자 전원, 아니면 엔진 목록 ∩ 방 참가자) − 보낸 사람.
5. 각 수신자에게 `{ type: 'focus', from, target: 정리된 target }`를 보낸다.

focus는 엔진 상태도, deadline도 바꾸지 않는다.

## 지우기와 다시 보내기

- 클라이언트는 `state`를 받을 때마다 표시 중인 다른 사람의 커서를 모두 지운다. 행동이 확정되거나 차례가
  넘어가면 항상 새 state가 오기 때문에, 오래된 커서가 남지 않는다.
- 커서를 보내던 사람이 새 state를 받은 뒤에도 여전히 고르는 중이면 현재 커서를 다시 보낸다. 예를 들어
  마피아 A가 먼저 확정해 state가 새로 나가도, 아직 고르는 B의 커서는 바로 복구된다.

## 클라이언트

- `App`: `focus` 메시지를 `focusMap: Record<닉네임, target>`에 저장하고, `state`를 받으면 비운다.
- `GameViewProps`에 선택 prop 두 개를 추가한다: `focus?: Record<string, unknown>`,
  `sendFocus?: (target: unknown) => void`. 쓰지 않는 뷰는 바뀌지 않는다.
- 공통 훅 `useFocusBroadcast(sendFocus, target, view)`:
  - target이 바뀌면 최대 100ms에 한 번 보내고, 마지막 값은 반드시 보낸다(trailing).
  - 새 view가 오면 target이 null이 아닐 때 다시 보낸다.
  - target이 null이 되거나 화면이 닫히면 `null`을 한 번 보낸다.
  - 뷰는 "지금 내가 무엇을 고르는 중인지"만 계산해 넘긴다.

### 게임별 표시

| 게임 | 보낸다 | 다른 사람에게 보인다 |
|---|---|---|
| 원카드 | 내 차례이고 낼 수 있을 때 `{ index: cursor }` | 차례인 상대의 뒷면 카드 한 장이 한 줄 올라가고 yellow. 커서가 그려지지 않은 카드(8장 초과분)에 있으면 `+N`을 yellow로 |
| 다빈치 | 내 차례일 때 겨누는 타일 | 해당 타일이 한 줄 올라가고 magenta, `영희님이 민수님의 2번 타일을 노리는 중`. 내 타일이면 `영희님이 내 2번 타일을 노리고 있습니다!`(bold) |
| 야추 | 점수 칸 선택 모드일 때 `{ category }`, 나가면 `null` | 해당 칸 줄에 `▶`와 bold, 주사위 아래에 `철수님이 풀하우스를 고민 중` |
| 마피아 | 밤에 마피아일 때 `{ target }` | 참가자 목록의 대상 옆에 `← 동료 철수 조준`(red) |

- 색 약속: cyan은 나와 내 커서, yellow/magenta는 다른 사람의 고민, red는 마피아 조준.
- 색이 없는 터미널에서도 구분되도록 색 외에 위치 변화(들어 올림)나 문구를 항상 함께 둔다.
- ascii 테마에는 `>`, `<-` 같은 대체 문자를 쓴다.

## 테스트 계획

core (엔진별 `focusRoute`)
- 원카드: 차례인 사람의 유효한 index는 `{ index }`로 전원 전달. 범위 밖·정수 아님·차례 아님은 `null`.
  덧붙인 추가 필드는 전달 target에서 빠진다.
- 다빈치: 공개된 타일·자기 타일·탈락자 타일은 `null`. 전달 target에 숫자(`value`)가 없다.
- 야추: 이미 기록한 칸·모르는 칸은 `null`.
- 마피아: 밤 마피아 → 살아 있는 마피아만. 밤 시민·의사·경찰·탈락자, 낮의 누구든 → `null`.
  이미 행동한 마피아 → `null`.

server (Room)
- 원카드 차례인 사람의 focus가 자기 자신을 뺀 방 전원에게 간다.
- 차례가 아닌 사람, 로비·결과 단계의 focus는 전달되지 않는다.
- 마피아 밤: 시민은 동료 마피아의 focus를 받지 못한다. 낮: 아무도 받지 못한다.
- 1초에 20개를 넘는 focus는 버려진다(주입한 시계로 검증).
- focus는 state를 새로 보내지 않고 deadline도 바꾸지 않는다.
- `focusRoute`가 없는 게임(라이어)은 아무것도 전달하지 않는다.

client
- `useFocusBroadcast`: 100ms 안의 연속 변경은 마지막 값 하나로 합쳐 보낸다. 새 view면 다시 보낸다.
  null로 바뀌면 null을 보낸다.
- App: `focus` 메시지는 저장되고, `state`가 오면 지워진다.
- 뷰별: 원카드 상대 카드 들어 올림과 `+N` 강조, 다빈치 "노리는 중" 문구와 내 타일 경고, 야추 `▶` 줄과
  문구, 마피아 `동료 조준` 문구.
- 모든 뷰: ascii 테마에서 ASCII·한글 외 문자가 새지 않는다.
